JSON/YAML/TOML 转换

在线 JSON、YAML、TOML 互转工具，支持 JSON 转 YAML、JSON 转 TOML、YAML 转 JSON、YAML 转 TOML、TOML 转 JSON、TOML 转 YAML 六种方向，自动识别粘贴内容格式，错误提示带行号，所有转换均在浏览器本地完成。

三种配置格式对比

格式语法风格注释典型用途
JSON 键名加双引号，花括号包裹，逗号分隔，最严谨 不支持 API 数据交换、前后端传输
YAML 缩进表示层级，键值用冒号加空格分隔 支持 # 注释 配置文件、CI/CD 流水线、Kubernetes
TOML 键 = 值，[表] 与 [[数组表]] 组织层级 支持 # 注释 项目配置（Cargo.toml、pyproject.toml）

说明：所有转换均在浏览器本地完成，数据不上传。TOML 与 YAML 输出固定为美化格式，JSON 输出可通过「美化输出」切换缩进与压缩；解析失败时会给出字段名、行号等定位信息，方便快速排查。

常见问题

三种格式之间转换会丢失数据吗？

JSON、YAML、TOML 都支持字符串、数字、布尔、数组与嵌套对象，常规结构转换不会丢失数据。需要注意：TOML 没有 null 类型，遇到 null 值会报错；TOML 的日期时间会保留为字符串；YAML 的锚点与别名等高级特性在转换中会被展开为普通结构。

为什么转换为 TOML 时报 null 错误？

TOML 规范本身没有 null 类型，这是为了保持类型系统的确定性。将 JSON 或 YAML 转换为 TOML 时，如果数据中包含 null，工具会明确指出出错的键，请先删除该键，或把值改为空字符串、0 等。

转换是在服务器上完成的吗？

不是。所有解析与生成都在你的浏览器本地完成，页面不会发起任何网络请求，输入内容不会上传到任何服务器，可以安全处理包含敏感信息的配置数据。
