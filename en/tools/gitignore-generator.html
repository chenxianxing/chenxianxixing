Frequently Asked Questions

      

        
Where should .gitignore be placed in the repository?

        
.gitignore is usually placed at the root of the Git repository, with the filename .gitignore. It applies to the entire repo; you can also place a .gitignore in subdirectories to affect only that directory and its children. A root-level .gitignore is the most common approach.

      

      

        
Can files that are already committed still be ignored?

        
No. .gitignore only affects files that are not yet tracked (untracked). If a file is already committed, you must first run git rm --cached  to remove it from the index (keeping the local file), after which it will be ignored.

      

      

        
How should secrets and sensitive config be handled?

        
Use the "Env/Secrets" group to ignore sensitive files like .env, *.pem and *.key, and commit a .env.example template without real secrets. Never commit private keys or production config to the repository.
