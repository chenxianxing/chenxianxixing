Frequently Asked Questions

What is the difference between UUID v4 and v7?

UUID v4 is made up entirely of random bits, so collisions are extremely unlikely but the values are unordered. As defined in RFC 9562, UUID v7 places a 48-bit millisecond timestamp at the front followed by random bits, so the generated IDs increase monotonically with time and are naturally ordered, making them better suited as database primary keys or for scenarios that need time ordering.

Will generated UUIDs repeat?

v4 uses cryptographically secure random numbers with a space of about 2^122, so the actual collision probability is negligible. v7 still contains random bits within a millisecond, so in theory there is a tiny chance of duplicates when generating a large number at the same instant, but it is more than enough for everyday use. This tool generates everything locally in the browser and does not depend on the network.

Why are UUIDs suitable as database primary keys?

UUIDs are globally unique and can be generated independently on multiple machines and services without conflicts, which is convenient for distributed systems and data merging. Among them, v7 has an ordered time prefix, which reduces database index fragmentation and improves write performance, making it a better primary key choice than v4.
