Frequently Asked Questions

What is the difference between symmetric (HS*) and asymmetric (RS*) signatures?

HS256/384/512 sign and verify with the same secret, so the issuer and the verifier must share it; these are common for internal services. RS256/384/512 use a pair of RSA keys: the private key signs and the public key verifies. The public key can be distributed openly and verifiers never need the private key, which suits multi-party collaboration or public exposure. For RS*, this tool only needs the public key to verify.

Why is http://localhost or https required for verification?

JWT verification relies on the browser Web Crypto API (crypto.subtle), which is only available in secure contexts (https or http://localhost). When you open the file directly by double-clicking it (file://), the browser disables this API and the tool shows a related error. Please access it through a local server.

Does a passing verification mean the token is valid and not expired?

A pass only means the signature is correct and the token was indeed issued by a party holding the corresponding key; it does not mean the token is unexpired or already active. Claims such as exp (expiration) and nbf (not before) must be checked by your own system. This tool displays these fields for you to inspect but does not judge business validity automatically.
